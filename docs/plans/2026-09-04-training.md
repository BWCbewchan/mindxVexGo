# Training workspace implementation plan

Authorized: local implementation only; no commit, push or deployment requested.

Build `/training` using the existing Blockly editor and portable controller bindings. Use the bundled sandboxed JavaScript interpreter with simulator-only APIs; never execute generated code with eval or forward it to hardware. Keep studio unchanged. Scope editor browser storage to training.

1. Add a deterministic 2D motion engine with mm coordinates, clockwise heading, bounded movement, circular robot / rectangular wall collision and a goal zone.
2. Bridge Blockly's existing generators and interpreter to the engine. Support drive/turn/wait, common control flow, variables/operators and My Blocks. Reject unsupported hardware blocks before execution. Implement Stop, Reset and a runnable demo.
3. Add a responsive training page with editor, virtual field, telemetry, console and existing function controls. Add image upload, field dimensions, start/goal/wall placement, field JSON download/upload and browser persistence.
4. Verify movement math, collision, interpreter-generated drive/turn/loops, file import, My Block controls, stop/cancellation, field export/import and mobile layout. Run build and studio regression checks. Report simulation limitations, including no automatic obstacle recognition from an image and no real-world physics equivalence.
